## Prompt

# Constitution.md

**Project:** Hackathon II – The Evolution of Todo
**Full Project Scope:** 5-Phase progression from In-Memory Python Console App to Cloud-Native AI-Powered Todo Chatbot on Kubernetes
**Development Paradigm:** Strictly Spec-Driven Development using Claude Code and Spec-Kit Plus

## Core Principles
- **Spec-Driven Development First**: Every feature, component, and architectural decision MUST originate from a written Markdown specification. All implementation is generated by Claude Code from refined specs.
- **No Manual Coding Allowed**: Participants must never write or edit production code manually. All code is generated by Claude Code. Any deviation disqualifies the submission for that phase.
- **Iterative Refinement**: Specifications must be iteratively clarified and refined until Claude Code produces correct, clean, and functional output.
- **Agentic Dev Stack Workflow**: Strictly follow Write spec → Generate plan → Break into tasks → Implement via Claude Code → Validate → Iterate.
- **Clean Code & Professional Standards**: All generated code must adhere to PEP8, use type hints, be modular, readable, and follow separation of concerns (UI, logic, storage, etc.).
- **Transparency & Auditability**: The entire development process (specs, plans, tasks, iterations, prompts) must be preserved in the repository for judging.

## Key Standards
- **Project Structure**:
  - Monorepo with Spec-Kit Plus organization (/.spec-kit/, /specs/ organized by type, /frontend/, /backend/, /src/ for Phase I).
  - Every phase must include a complete specs history folder showing evolution.
  - CLAUDE.md files at root and subdirectories documenting Claude instructions and prompts.
  - README.md with clear setup and run instructions.
- **Feature Implementation**:
  - Phase I–V must implement all Basic Level features (Add, Delete, Update, View, Mark Complete).
  - Later phases progressively add Intermediate and Advanced features as capacity allows.
  - Phases III–V must include a fully functional natural-language AI chatbot capable of managing todos.
- **Technology Compliance**:
  - Phase I: Python 3.13+, UV, in-memory storage only.
  - Phase II: Next.js 16+ (App Router), FastAPI, file-based persistence.
  - Phase III: Natural language chatbot interface.
  - Phase IV: Docker, Minikube, Helm, kubectl-ai, kagent.
  - Phase V: Kafka, Dapr, DigitalOcean Kubernetes (DOKS).

## Constraints
- **No Manual Code Edits**: Refinement happens only through spec improvement and re-generation.
- **Windows Development**: Must use WSL 2 with Ubuntu 22.04.
- **Submission Requirements**: Public GitHub repository, Demo video ≤ 90 seconds per phase, All required files.
- **Deadlines**: Phase submissions on specified Sundays (late submissions accepted for evaluation as of December 30, 2025).

## Success Criteria
- **Functional Deliverables**: Each phase produces a working, demonstrable application meeting the specified features and technology stack.
- **Process Adherence**: Judges can trace every line of code back to a spec, plan, and Claude Code generation step.
- **Code Quality**: Generated code is clean, typed, modular, and follows best practices.
- **AI Agent Capability**: By Phase III, the chatbot intelligently interprets and executes natural-language todo commands.
- **Deployment Success**: Phase IV runs locally on Minikube; Phase V runs on DigitalOcean Kubernetes with event-driven components.
- **Bonus Achievement**: Implementation of reusable intelligence (subagents/skills), cloud-native blueprints, Urdu support, or voice commands earns additional points.
