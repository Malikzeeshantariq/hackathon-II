## Prompt

Implement Basic Level Features for Phase I: In-Memory Python Console Todo Application
Target application: Command-line Todo app that stores tasks entirely in memory (no files or databases)
Focus: Implement the 5 Basic Level (Core Essentials) features as the complete and minimal viable functionality for Phase I
Success criteria:

Users can add new tasks with a title and description
Users can view the full list of tasks with clear status indicators (e.g., [ ] for incomplete, [✓] for complete) and unique auto-incrementing IDs
Users can mark any task as complete or incomplete (toggle status) by ID
Users can update the title and/or description of any existing task by ID
Users can delete any task by ID
The app runs in an interactive command-loop with a simple text-based menu or command system (e.g., commands like "add", "list", "complete 3", "update 2", "delete 1", "exit")
After every operation, the updated task list is displayed automatically or on demand
Edge cases handled gracefully: empty list shows friendly message, invalid ID shows clear error, no crashes

Constraints:

Storage: In-memory only (e.g., list of dataclasses or dictionaries)
Language: Python 3.13+
Dependencies: No external packages beyond standard library (keep it minimal for Phase I)
Code generation: All implementation must be generated by Claude Code from this spec and subsequent refinements
No manual code writing or editing allowed
Project structure: Follow Spec-Kit Plus standards with /src/ containing generated Python files, specs history preserved
CLI interface: Simple, readable, text-based (no GUI or web components)

Not building:

Persistent storage (files, databases)
User authentication or multi-user support
Intermediate features (priorities, tags, search, filter, sort)
Advanced features (due dates, recurring tasks, reminders)
Any web, API, or deployment components
Complex CLI libraries (e.g., no Click, Typer, or Rich unless absolutely necessary and justified later)

This specification covers only the required Basic Level functionality for Phase I submission. Future phases will extend this foundation.
